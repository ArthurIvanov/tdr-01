# Чеклист доступности: React-дизайн-система

Базовый уровень: **WCAG 2.2 AA**. Номера в скобках — критерии успеха WCAG.

Источники: [WCAG 2.2](https://www.w3.org/TR/WCAG22/), [WAI-ARIA Authoring Practices (APG)](https://www.w3.org/WAI/ARIA/apg/), [ARIA in HTML](https://www.w3.org/TR/html-aria/), [Accessible Name and Description Computation](https://www.w3.org/TR/accname-1.2/), [Understanding WCAG](https://www.w3.org/WAI/WCAG22/Understanding/), [React: Accessibility](https://react.dev/learn/accessibility), [MDN: ARIA](https://developer.mozilla.org/docs/Web/Accessibility/ARIA), [Radix UI](https://www.radix-ui.com/primitives/docs/overview/accessibility) / [React Aria](https://react-spectrum.adobe.com/react-aria/) как эталонные реализации.

## 1. Дизайн

### 1.1 Цвет

- [ ] **Контраст текста**: ≥ 4.5:1; крупный текст (≥ 24px или ≥ 18.66px bold) ≥ 3:1 (1.4.3)
- [ ] **Контраст не-текста**: границы полей, иконки, фокус-кольцо, состояния контролов, графики ≥ 3:1 к соседним цветам (1.4.11)
- [ ] **Контраст проверен для каждой пары токенов** `foreground × background` во всех темах (light / dark / high-contrast) и во всех состояниях (default, hover, active, disabled-информативный, selected, error)
- [ ] **Цвет — не единственный носитель смысла**: ошибка, успех, выбранное, обязательное, ссылка в тексте дублируются иконкой, текстом, формой или подчёркиванием (1.4.1)
- [ ] **Контраст ссылок в тексте**: отличие от окружающего текста ≥ 3:1 или есть подчёркивание (1.4.1)
- [ ] **Состояние disabled** не требует контраста, но не должно скрывать важную информацию; для критичной информации используйте `readonly` / пояснение
- [ ] **Семантические токены контраста**: в системе заранее закреплены пары `on-surface`, `on-primary`, `on-error` с гарантированным контрастом, а не свободный выбор цвета
- [ ] **Проверка на цветовую слепоту**: протанопия, дейтеранопия, тританопия, ахроматопсия (симуляция в Figma / DevTools)
- [ ] **Поддержка системных режимов**: `prefers-color-scheme`, `prefers-contrast: more`, `forced-colors: active` (Windows High Contrast)
- [ ] **Данные и графики**: различаются не только цветом (паттерн, форма маркера, подписи), у серий ≥ 3:1 между соседями

### 1.2 Взаимодействие

- [ ] **Фокус виден всегда**: контур ≥ 2px, контраст ≥ 3:1 к фону и к самому элементу, не перекрывается другими элементами (2.4.7, 2.4.11, 2.4.13)
- [ ] **Единый стиль фокуса** задан токеном; используйте `:focus-visible`, а не отключайте `outline`
- [ ] **Размер цели**: ≥ 24×24 CSS px (минимум WCAG 2.2, 2.5.8); для основных действий и мобайла рекомендуется ≥ 44×44
- [ ] **Достаточные отступы** между интерактивными элементами, особенно в плотной (compact) теме
- [ ] **Состояния описаны для каждого компонента**: default, hover, focus, active, disabled, loading, error, selected, expanded, read-only
- [ ] **Hover и focus равноценны**: любая информация или действие по hover доступны и по focus; подсказка не исчезает при движении курсора на неё и закрывается по `Esc` (1.4.13)
- [ ] **Нет действий только по жесту**: для drag-and-drop, свайпа, pinch, long press есть альтернатива одним касанием / кликом (2.5.1, 2.5.7)
- [ ] **Отмена случайного нажатия**: действие срабатывает на `up`-событии, либо есть возможность отменить (2.5.2)
- [ ] **Порядок фокуса логичен** и совпадает с визуальным порядком; на макете обозначена последовательность Tab для сложных компонентов (2.4.3)
- [ ] **Клавиатурный сценарий описан в спецификации** компонента: какие клавиши что делают (по APG)
- [ ] **Фокус не теряется**: после закрытия модалки, удаления элемента, смены вида указано, куда уходит фокус
- [ ] **Обратная связь о статусе**: загрузка, успех, ошибка видимы и озвучиваются; не исчезают слишком быстро (4.1.3, 2.2.1)
- [ ] **Ошибки форм**: текст объясняет, что произошло и как исправить; расположен рядом с полем; поле помечено как ошибочное не только цветом (3.3.1, 3.3.3)
- [ ] **Подписи и подсказки**: видимая метка у каждого поля, не placeholder; placeholder не заменяет label (3.3.2)
- [ ] **Анимация**: нет мигания > 3 раз в секунду (2.3.1); для движения есть `prefers-reduced-motion`; автоматическое движение > 5 с можно остановить (2.2.2)
- [ ] **Тайм-ауты**: пользователь предупреждён и может продлить (2.2.1)
- [ ] **Масштаб и reflow**: макет работает при 200% зума текста и при 320 CSS px ширины без горизонтального скролла (1.4.4, 1.4.10); текст не обрезается при увеличенном интервале (1.4.12)
- [ ] **Ориентация**: нет принудительной портретной / альбомной (1.3.4)
- [ ] **Единообразие**: одинаковые функции выглядят и называются одинаково; расположение справки и навигации стабильно (3.2.3, 3.2.4, 3.2.6)
- [ ] **Иконки без текста** имеют задокументированный текстовый аналог (accessible name)

### 1.3 Передача в разработку

- [ ] У компонента в Figma есть аннотации: роль, accessible name, порядок фокуса, клавиши, live-сообщения
- [ ] Контраст и размеры зафиксированы токенами, а не значениями в макете
- [ ] Определены контент-правила: длина меток, тексты ошибок, альтернативные тексты

## 2. Разработка

### 2.1 Семантика прежде всего

- [ ] **Нативный HTML первым**: `<button>`, `<a href>`, `<input>`, `<select>`, `<dialog>`, `<details>`, `<fieldset>` вместо `div` с ролями. Первое правило ARIA: не используйте ARIA, если есть нативный элемент
- [ ] **Кнопка и ссылка различаются**: `<button>` выполняет действие, `<a href>` переходит; никаких `<a>` без `href` и `<div onClick>`
- [ ] **Структура страницы**: `header`, `nav`, `main`, `footer`, `aside`; один `h1`; заголовки идут по порядку, уровень выбирается пропом, отделённым от визуального размера (`as` / `level`)
- [ ] **Списки, таблицы, формы** размечены своими элементами (`ul/ol`, `table/th[scope]/caption`, `form`)
- [ ] **Язык**: `lang` на `<html>`, на смене языка внутри контента — `lang` на элементе (3.1.1, 3.1.2)
- [ ] **Нет role, дублирующей неявную роль** (`<button role="button">`); нет конфликтующих (`<h2 role="tab">`)

### 2.2 Имена, описания, состояния (ARIA)

- [ ] **У каждого интерактивного элемента есть accessible name**: видимый текст, `<label>`, `aria-labelledby`, `aria-label` (приоритет именно в таком порядке)
- [ ] **Видимая метка входит в accessible name** (2.5.3 Label in Name)
- [ ] **Иконки-кнопки**: иконка `aria-hidden="true"` + имя на кнопке; декоративные изображения `alt=""`, информативные — осмысленный `alt`
- [ ] **Состояния через ARIA и синхронны с UI**: `aria-expanded`, `aria-pressed`, `aria-selected`, `aria-checked`, `aria-current`, `aria-disabled`, `aria-busy`
- [ ] **Связи через id**: `aria-describedby` для подсказок и ошибок, `aria-controls` для связанных регионов; id генерируются `useId()` (стабильны при SSR)
- [ ] **Ошибки**: `aria-invalid="true"` + `aria-describedby` на текст ошибки; для обязательных — `required`, не только звёздочка
- [ ] **Живые области**: `role="status"` / `aria-live="polite"` для статусов, `role="alert"` только для срочных ошибок; контейнер live-региона есть в DOM заранее, меняется только содержимое
- [ ] **Нет `aria-hidden` на фокусируемых элементах**; скрытое содержимое убирается через `hidden` / `inert` / `display:none`
- [ ] **Скрытый для глаз текст**: класс `visually-hidden` (clip-подход), а не `display:none`
- [ ] **Нет `title` как единственного источника имени или подсказки**

### 2.3 Клавиатура и фокус

- [ ] **Весь функционал доступен с клавиатуры**; нет ловушек фокуса, кроме модальных (2.1.1, 2.1.2)
- [ ] **Нативная клавиатурная модель сохранена**: `Enter` / `Space` на кнопках, `Enter` на ссылках; кастомные виджеты следуют APG
- [ ] **Составные виджеты** (tabs, menu, listbox, grid, tree, radio group): один tab-stop, навигация стрелками, `Home` / `End`; реализован *roving tabindex* или `aria-activedescendant`
- [ ] **`tabindex`**: только `0` и `-1`; положительные значения запрещены
- [ ] **Модальные окна**: фокус переносится внутрь при открытии, удерживается (focus trap или `inert` на фоне), `Esc` закрывает, фокус возвращается на инициатор; `role="dialog"` + `aria-modal="true"` + имя
- [ ] **Popover, dropdown, tooltip**: закрытие по `Esc`, фокус не теряется, подсказка не единственный путь к информации
- [ ] **Skip-link** на основной контент (2.4.1)
- [ ] **Управление фокусом при динамике**: после навигации SPA фокус и заголовок страницы обновляются, смена route озвучивается; при удалении элемента фокус переходит на логичного соседа
- [ ] **Фокус не скрыт** `position: sticky` / фиксированными панелями: используйте `scroll-padding` (2.4.11)
- [ ] **`:focus-visible`** используется для стилей; `outline: none` без замены запрещён
- [ ] **Redundant entry и auth**: не требовать повторно вводить одно и то же, разрешён paste и менеджеры паролей (3.3.7, 3.3.8); корректные `autocomplete` на полях (1.3.5)

### 2.4 React-специфика

- [ ] **Компоненты принимают и пробрасывают** `ref`, `id`, `aria-*`, `data-*`, `className` (через `...rest`) на корневой интерактивный элемент
- [ ] **Нативные пропсы не перехватываются**: `disabled`, `type`, `name`, `form`, `autoComplete` и пр. доходят до DOM
- [ ] **`useId()`** для связей label / description / controls; никаких `Math.random()` или счётчиков в рендере
- [ ] **Fragment вместо лишних `div`**, чтобы не ломать семантику списков, таблиц, `dl`
- [ ] **`<label htmlFor>`** либо оборачивающий `label`; кастомные `Field`-компоненты автоматически связывают label, hint и error
- [ ] **Порталы** (modal, popover): сохраняют порядок фокуса и контекст темы; фокус возвращается корректно
- [ ] **Управление фокусом** через `ref.current.focus()` в `useEffect` / `useLayoutEffect`, с учётом `preventScroll`
- [ ] **Контролируемое и неконтролируемое состояние**: оба режима сохраняют синхронность ARIA-атрибутов
- [ ] **Полиморфизм (`as` / `asChild`)**: при смене тега сохраняются роль, поведение клавиш и атрибуты (`<a>` как кнопка получает `role`, `Space`)
- [ ] **События**: используйте `onClick` на нативных элементах (клавиатура даёт click автоматически); для кастомных — обработка `onKeyDown`, а не только мыши
- [ ] **Анимации и переходы**: учитывают `prefers-reduced-motion` (CSS и JS); состояния `exit` не оставляют невидимый, но фокусируемый DOM
- [ ] **Списки и сообщения**: у элементов стабильные `key`, чтобы фокус не прыгал при перерисовке
- [ ] **SSR / гидратация**: ARIA-атрибуты и id совпадают на сервере и клиенте
- [ ] **Готовые примитивы**: для сложных виджетов (Dialog, Select, Combobox, Menu, Tabs, Tooltip) использовать проверенные headless-библиотеки (Radix, React Aria, Ariakit), а не писать с нуля

### 2.5 Адаптивность и предпочтения пользователя

- [ ] Размеры шрифтов и отступов в `rem` / относительных единицах; не блокируется зум (`user-scalable=no` запрещён) (1.4.4)
- [ ] Нет `overflow: hidden` и фиксированной высоты, обрезающих текст при увеличении
- [ ] Поддержка `forced-colors` (использовать системные цвета, не полагаться на `background-image` для смысла)
- [ ] Поддержка `prefers-reduced-motion`, `prefers-contrast`, `prefers-color-scheme`
- [ ] Контент доступен при отключённом CSS в логичном порядке чтения (DOM-порядок = визуальный порядок)

## 3. Автоматизация и проверка

### 3.1 В процессе разработки

- [ ] **ESLint**: `eslint-plugin-jsx-a11y` (strict-конфиг) подключён и блокирует CI
- [ ] **Unit / компонентные тесты**: `@testing-library/react` с запросами по ролям (`getByRole`, `getByLabelText`), клавиатурные сценарии через `user-event`
- [ ] **Автопроверка axe**: `jest-axe` / `vitest-axe` в тестах компонентов, `@storybook/addon-a11y` в историях
- [ ] **E2E**: Playwright + `@axe-core/playwright` на ключевых сценариях
- [ ] **Visual-регрессия** покрывает состояния focus, error, high-contrast, dark
- [ ] **Тесты токенов**: автоматическая проверка контраста пар цветов в каждой теме

### 3.2 Ручная проверка (автоматика ловит ~30–40% проблем)

- [ ] Только клавиатура: пройти все сценарии компонента
- [ ] Скринридер: VoiceOver (macOS / iOS), NVDA или JAWS (Windows), TalkBack (Android)
- [ ] Зум 200% и 400%, ширина 320px
- [ ] High-contrast / forced-colors, dark mode, reduced motion
- [ ] Touch: размер целей, альтернативы жестам

### 3.3 Definition of Done для компонента

- [ ] Нативная семантика или ARIA по APG
- [ ] Клавиатурная модель задокументирована и реализована
- [ ] Accessible name, описание, состояния
- [ ] Все состояния проходят контраст во всех темах
- [ ] Фокус виден и управляем
- [ ] axe без нарушений, ручная проверка со скринридером пройдена
- [ ] В документации Storybook: раздел «Accessibility» (роли, клавиши, примеры использования и антипримеры)
- [ ] Для сложных виджетов — запись о выбранной основе (свой код или headless-библиотека) и известных ограничениях

## 4. Быстрые правила (шпаргалка)

| Тема | Правило |
|---|---|
| Контраст текста | 4.5:1 (крупный 3:1) |
| Контраст UI и фокуса | 3:1 |
| Размер цели | ≥ 24×24 px (лучше 44×44) |
| Фокус | видимый, ≥ 2px, `:focus-visible` |
| Цвет | никогда единственный носитель смысла |
| ARIA | сначала нативный HTML, ARIA только дополняет |
| Имя | у всего интерактивного, видимая метка входит в имя |
| `tabindex` | только `0` и `-1` |
| Dialog | фокус внутрь, удержание, `Esc`, возврат фокуса |
| Составные виджеты | один tab-stop + стрелки (APG) |
| Анимация | уважать `prefers-reduced-motion` |
| Проверка | линтер + axe + клавиатура + скринридер |
